## User story

**As a** coding agent shipping ChaosLab stories
**I want to** install `pre-commit` and have a working `.pre-commit-config.yaml` running ruff, ty, ESLint, Prettier, gitleaks, markdownlint, conventional-commits, plus a placeholder local hook for the 400-line guard
**So that** every commit is auto-formatted, linted, type-checked, and secret-scanned before it ever touches GitHub — the local discipline layer that mirrors CI

- `.pre-commit-config.yaml` — NEW — full config copy-pasted verbatim from `docs/coding-standards.md` §"Pre-commit hooks (full `.pre-commit-config.yaml`)". The coding agent must NOT modify files outside this map without re-checking CLAUDE.md.

## Acceptance criteria (BDD — machine-verifiable)

```
Given story-1.1 has completed (pyproject.toml + uv workspace ready)
When the coding agent runs `uv add --dev pre-commit`
Then `uv pip list | grep pre-commit` exits 0
And pyproject.toml [dependency-groups.dev] contains "pre-commit"

Given .pre-commit-config.yaml has been created
When `test -f .pre-commit-config.yaml` runs
Then exit code is 0

Given the .pre-commit-config.yaml has been written
When `grep -E "^\s*-\s+id:\s+(ruff|ruff-format|ty-check|check-max-lines|eslint|prettier|gitleaks|markdownlint|conventional-pre-commit)" .pre-commit-config.yaml | wc -l` runs
Then output ≥ 9 (all 9 hook ids present)

Given pre-commit is installed in the .venv
When `uv run pre-commit install --hook-type pre-commit --hook-type commit-msg` runs
Then exit code is 0
And `test -f .git/hooks/pre-commit && test -f .git/hooks/commit-msg` exits 0

Given .pre-commit-config.yaml references local hooks
When `uv run pre-commit run --all-files` runs
Then it exits with status 0 OR with status 1 with output containing "scripts/check_max_lines.py" (the stub failure is expected pre-1.3)
And no hook fails for a non-stub reason (i.e., ruff, eslint, gitleaks, markdownlint all completed even if zero files matched)

Given CLAUDE.md was updated
When `grep -E "pre-commit" CLAUDE.md` runs
Then exit code is 0
```

## Notes for coding agent

- The full `.pre-commit-config.yaml` content is in `docs/coding-standards.md` §"Pre-commit hooks (full `.pre-commit-config.yaml`)" — copy verbatim. Do not improvise hook versions; the `rev:` pins are deliberate (`v0.8.0` for ruff, `v5.0.0` for pre-commit-hooks, `v8.21.0` for gitleaks, `v0.43.0` for markdownlint, `v3.6.0` for conventional-pre-commit).
- The `check-max-lines` hook in this story is a STUB. It calls `python3 scripts/check_max_lines.py --strict`. The script does NOT exist yet — story-1.3 creates it. That hook will error with `python3: can't open file 'scripts/check_max_lines.py'` until 1.3 lands. That is INTENTIONAL — the verification accepts this single failure mode.
- The `ty-check` local hook calls `uv run ty check apps/chaoslab-agent apps/target-agent`. Those source dirs don't have any `.py` files yet — `ty` will likely succeed with "nothing to check" or fail silently. Either is fine.
- The `eslint` and `prettier` hooks call `pnpm --filter chaoslab-web exec ...`. Until story-7.1, `apps/chaoslab-web/` only has a minimal `package.json` — these hooks will skip gracefully when no matching files exist.
- Do NOT add the `--strict` flag to `pre-commit install` itself — `pre-commit install --hook-type pre-commit --hook-type commit-msg` is the canonical invocation.
- After running `pre-commit install`, git automatically wires the hooks. The story is done once `.git/hooks/pre-commit` and `.git/hooks/commit-msg` exist.
- Reference: `best-practices/02 §10` (pre-commit hook integration) and `coding-standards.md` §"Pre-commit hooks".
