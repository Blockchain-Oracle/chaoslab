## User story

**As a** Patcher sub-agent (S6.4) that must emit a single canonical recipe object — AND a frontend (`chaoslab-web`) that renders the recipe in the Receipt card — AND a GitLab MR emitter (S6.6) that serializes the recipe into an MR description
**I want to** depend on a single pydantic v2 schema set (`FailureCluster`, `PromptPatch`, `ToolValidationDiff`, `HardeningRecipe`) exported BOTH as Python types (for backend imports) AND as a JSON Schema at `packages/shared-types/hardening-recipe.json` (for TypeScript-side ingestion)
**So that** the recipe artifact is cross-language type-safe (Python ←→ TypeScript via JSON Schema), the contract is canonical (no drift between backend emission and frontend rendering), and every downstream consumer (Markdown emitter S6.5, GitLab emitter S6.6, Receipt card) imports from one place — matching the `architecture.md` §"Hardening recipe artifact format (locked)" section byte-for-byte

### Required pydantic schemas — verbatim from `architecture.md`

The `architecture.md` §"Hardening recipe artifact format (locked)" section is the canonical contract. Implement EXACTLY:

```python
# apps/chaoslab-agent/src/chaoslab_agent/patcher/recipe.py
from __future__ import annotations
import secrets
from typing import Any, Literal
from pydantic import BaseModel, Field, model_validator


FaultClass = Literal[
    "malformed_tool_output",
    "prompt_injection",
    "context_poisoning",
    "latency_spike",
]


class FailureCluster(BaseModel):
    cluster_id: str = Field(pattern=r"^cluster_[a-z0-9]{8}$")
    root_cause: str = Field(min_length=1)
    failure_count: int = Field(ge=1)
    span_ids: list[str] = Field(min_length=1)
    fault_classes: list[FaultClass] = Field(min_length=1)


class PromptPatch(BaseModel):
    section: Literal["system_prompt", "tool_description", "few_shot_example"]
    operation: Literal["insert", "replace", "append"]
    before: str | None = None
    after: str = Field(min_length=1)

    @model_validator(mode="after")
    def _replace_requires_before(self) -> "PromptPatch":
        if self.operation == "replace" and self.before is None:
            raise ValueError("PromptPatch.before is required when operation == 'replace'")
        return self


class ToolValidationDiff(BaseModel):
    tool_name: str = Field(min_length=1)
    operation: Literal["add_input_validator", "add_output_validator", "add_retry_policy", "add_timeout"]
    code_patch: str = Field(min_length=1)  # unified diff format


class HardeningRecipe(BaseModel):
    recipe_id: str = Field(pattern=r"^recipe_[a-z0-9]{12}$")
    target_agent_id: str = Field(min_length=1)
    generated_at: str = Field(min_length=1)  # ISO 8601
    cluster_set: list[FailureCluster] = Field(min_length=1)
    prompt_patches: list[PromptPatch] = Field(default_factory=list)
    tool_validation_diffs: list[ToolValidationDiff] = Field(default_factory=list)
    regression_test_cases: list[dict[str, Any]] = Field(default_factory=list)
    estimated_resilience_improvement: float = Field(ge=0.0, le=1.0)
    metadata: dict[str, Any] = Field(default_factory=dict)


def new_recipe_id() -> str:
    return f"recipe_{secrets.token_hex(6)}"  # 12 hex chars
```

### Export script shape

```python
# scripts/export_recipe_schema.py
"""Export HardeningRecipe JSON Schema to packages/shared-types/."""
from __future__ import annotations
import json
import sys
from pathlib import Path

# Add chaoslab-agent src to path so this script can run from repo root
REPO_ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(REPO_ROOT / "apps/chaoslab-agent/src"))

from chaoslab_agent.patcher.recipe import HardeningRecipe  # noqa: E402


def main() -> int:
    schema = HardeningRecipe.model_json_schema()
    out_path = REPO_ROOT / "packages/shared-types/hardening-recipe.json"
    out_path.parent.mkdir(parents=True, exist_ok=True)
    out_path.write_text(json.dumps(schema, indent=2, sort_keys=True) + "\n", encoding="utf-8")
    print(f"wrote {out_path}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

### Architecture context

- **`architecture.md` §"Hardening recipe artifact format (locked)" is canonical.** This story implements it byte-for-byte (modulo pydantic v2 syntax additions like `Field(min_length=1)` instead of bare `str`). If you discover a discrepancy with `architecture.md`, **`architecture.md` wins** — open an issue, don't silently diverge.
- **Cross-language type sharing:** `packages/shared-types/hardening-recipe.json` is consumed by `chaoslab-web` to generate TypeScript types via `json-schema-to-typescript` (deferred to a later frontend story). Commit the generated JSON so the frontend build doesn't need Python.
- **`new_recipe_id()` uses `secrets.token_hex(6)` = 12 hex chars** matching the `recipe_[a-z0-9]{12}$` regex. Do NOT use `uuid.uuid4()` — UUIDs have hyphens and `[a-f0-9]` mixed-case in some libraries.
- **`PromptPatch.before` is nullable for `insert`/`append` ops, required for `replace`.** The `model_validator` enforces this. Per `architecture.md`: `before: str | None  # for replace ops` — this annotation is preserved.
- **`ToolValidationDiff.code_patch` is unified-diff format.** Story 6.5 (Markdown emitter) renders this in a `\`\`\`diff` code block; Story 6.6 (GitLab emitter) commits the patch as a real diff applied via `git apply`. The schema enforces non-empty but does NOT validate the diff format — that's a runtime concern.
- **`regression_test_cases: list[dict[str, Any]]`** is intentionally loose-typed. These get serialized to a Phoenix dataset (per `architecture/04 §6.3`), so the schema is determined downstream by the Phoenix dataset format. The pydantic model just says "any dict."
- **§14 gate:** zero mocks. The schema validators are real pydantic; the export script is real I/O.

### JSON Schema export gotchas

- **pydantic v2's `model_json_schema()` defaults to draft-2020-12.** Validate with `jsonschema.Draft202012Validator.check_schema(schema)`.
- **`$defs` placement:** pydantic v2 nests definitions under `$defs` at the top level. The shell verification asserts on `$defs.FailureCluster`, `$defs.PromptPatch`, `$defs.ToolValidationDiff` being present. If your test fails, check whether pydantic flattened them inline (older pydantic v2 patches did this differently).
- **Stable output:** `json.dumps(..., sort_keys=True, indent=2)` ensures deterministic diffs in git. Without `sort_keys`, pydantic's key order can vary between runs.
- **Trailing newline:** end the file with `\n` so editors don't add one + cause diff noise.

### Test guidance

- **Pydantic structural assertions:** for every Literal field, write one test per valid value + one test per invalid value. The `Literal["system_prompt", "tool_description", "few_shot_example"]` on `PromptPatch.section` gets 4 tests total (3 valid + 1 invalid).
- **Round-trip test:** instantiate a fully-populated `HardeningRecipe`, serialize with `.model_dump_json()`, parse back as dict, validate against the exported JSON Schema with `jsonschema.validate`. This catches drift between pydantic's internal schema and the exported file.
- **No LLM calls in this story.** Recipe schema is pure pydantic + JSON I/O. The `respx`/HTTP boundary doesn't apply.

### Known pitfalls

- **`Field(min_length=1)` on `str` works in pydantic v2.** Don't use the v1 syntax `constr(min_length=1)`.
- **`Literal` with `from typing import Literal`** is fine on Python 3.12. Don't import from `typing_extensions`.
- **`HardeningRecipe.generated_at` is a string** (ISO 8601) per `architecture.md`, NOT a `datetime`. The Markdown emitter (S6.5) wants the string as-is for rendering; converting to `datetime` adds serialize/deserialize round-trip cost without benefit. If a future story needs datetime parsing, do it at the boundary, not in the schema.
- **`secrets.token_hex(n)` returns `2n` hex chars** — `secrets.token_hex(6)` is 12 chars, `secrets.token_hex(4)` is 8 chars. Test this in the regex assertion.
