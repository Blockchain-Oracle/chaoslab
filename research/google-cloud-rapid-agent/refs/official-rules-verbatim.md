## Disqualification Risks Specific to ChaosLab (audit before submit)

These are the FOUR specific items I'd lose sleep over before submission. Each one is a Stage 1 fail if it slips through.

### Risk 1 — AI-usage limitation (§7B) — HIGHEST RISK

> "All other artificial intelligence tools are not permitted."

**What this means:** In our submitted runtime, the ONLY permissible AI tools are Google Cloud AI (Gemini models, BigQuery ML, Vertex AI APIs, Agent Builder) + Arize built-in AI features. Banned AS RUNTIME DEPENDENCIES: anthropic/claude, cursor, copilot, openai, langchain-as-primary, langgraph, llamaindex, perplexity, mistral, any non-Google LLM.

**Where it could slip in:**

1. `pyproject.toml` (root + per-app) — explicit dep
2. `package.json` (root + per-app) — explicit dep, transitive via `next-ai` plugins
3. `apps/chaoslab-agent/src/**` — accidental import
4. `apps/target-agent/src/**` — even if the target IS a LangChain agent (Tier 2 target via OpenInference), the SUBMITTED runtime can't ship LangChain as primary
5. `.env.example` or CI env vars — `ANTHROPIC_API_KEY` etc. as named env vars
6. Cloud Run env vars baked into the deploy YAML
7. Dockerfile `pip install`s
8. Demo seed script (`scripts/demo_seed.py`) — must not invoke non-Google LLMs

**Audit pattern (pre-submit, S8.x):**

```bash
grep -rE "(anthropic|claude|cursor|copilot|langchain|langgraph|llamaindex|perplexity|mistral)" \
  apps/ pyproject.toml package.json apps/*/package.json apps/*/pyproject.toml \
  .github/workflows/ infra/ apps/*/Dockerfile apps/*/.env.example \
  2>/dev/null
# Expected: 0 matches in runtime deps. ALL matches must be:
#   - in tests/ (testing cross-framework adapters)
#   - in docs/research/ (discussing competing tools we don't use)
#   - in dev-time tooling that doesn't ship in the Docker image
```

**Tier 2 cross-framework note:** ChaosLab's Tier 2 design (attack LangChain/CrewAI/OpenAI Agents SDK targets via OpenInference instrumentors) is COMPATIBLE with §7B — those instrumentors are PASSIVE telemetry that read target traces, not active LLM dependencies in our runtime. The TARGET agent runs as a separate Cloud Run service we don't own at deploy time (cross-framework demos use externally-hosted targets). Verify the deployed `target-agent` (S2.4) uses ONLY Google ADK + Gemini for the in-repo example target.

### Risk 2 — Newly Created (§7B)

> "Projects must be newly created by the entrant during the Contest Period. The Project must be Your original creation not a modification or extension of Your or anyone else's existing work."

**ChaosLab status:**

- Research / spec / domain knowledge: predates the contest (started ~2026-06-02). **This is fine** — the rule covers the Project (code), not the research that informed it.
- Agent code: started 2026-06-03 with S1.1 monorepo init. ✅
- NOTICE attribution to deepankarm/agent-chaos: explicit "no code copied" per ADR-006 amended. ✅
- No vendored third-party agent code anywhere in `apps/`. ✅

**Audit pattern:** verify NOTICE matches actual vendoring; verify no `git submodule`; verify no commit in `apps/` predates 2026-05-05 (none can, since the repo was initialized 2026-06-03).

### Risk 3 — Demo Video Compliance (§7B)

Video requirements that are easy to miss:

1. **≤3 minutes** — only first 3 min evaluated. Cut at 3:00 with hard stop.
2. **English (or English subtitles)** — ChaosLab demo uses English narration; subtitles optional but recommended for clarity.
3. **No third-party trademark/sponsorship indication** — but using a Partner's product UI (Phoenix dashboard, GitLab MR view) is INTENDED USE, not a third-party-sponsorship claim. Show them naturally; don't add explicit "Sponsored by X" overlays.
4. **No offensive/defamatory/sexual/profane content** — standard.
5. **Original work, not contain third-party-owned content** — careful with stock music. Use royalty-free.
6. **Publicly visible on YouTube or Vimeo** — public unlisted is fine; password-protected is NOT.

**Open question:** can the demo include the audit-notes.md "ChaosLab" branding, "Chaos engineering for AI agents" tagline — yes, those are our own marks.

### Risk 4 — License Detectability (§12)

> "[The license] should be detectable and visible at the top of the repository page (in the About section)."

**Audit pre-submit:**

1. Repo settings → About → "License" field shows "Apache License 2.0" ✓ (auto-detected by GitHub from LICENSE file at repo root)
2. LICENSE file at repo root, NOT in a subdir
3. LICENSE filename is exactly `LICENSE` (no extension), `LICENSE.md`, `LICENSE.txt`, or `COPYING` — anything else and GitHub's license-detection fails silently
4. First line of LICENSE is "Apache License" (verified by S1.1 acceptance test ✓)
