# SPEC — Phoenix Audit frontend port

## Goal

Port the designer's complete Phoenix Audit React/HTML prototype (`/Users/abu/Downloads/Phoenix Audit/` — 10 JSX files, ~155 KB of design-system CSS + fixtures + 11 routes) into `apps/phoenix-audit-web/` as a real production Next.js 16 + TypeScript app. The designer shipped every screen Maya needs end-to-end — landing, new-audit wizard, live audit chamber, pre-recorded replay, audit history, target agents (list + detail), hardening recipe view, signed PDF preview with Cloud KMS signing animation, continuous monitoring config, settings, error/empty/blocked-state gallery, plus the 1200×630 Open Graph image. The "cascade-flip" demo moment + the seal-spin signing moment + the timeline-driven scrub-safe replay all already work in the prototype. Our job is to make it shippable: TypeScript strict, real routing via Next.js App Router, real fixtures with backend-aligned types, the live audit route consuming the real `phoenix-audit-agent` `/stream` SSE wire (with timeline fallback for per-probe events the backend doesn't emit yet), and the existing CI gates passing.

## Constraints

- **Stack:** Next.js 16 App Router + React 19 + TypeScript 5.x strict + Tailwind 4 CSS-first + pnpm workspace. Node ≥20 (we have 25). Pinned per `docs/architecture.md`.
- **Designer's prototype is the canonical visual answer.** It supersedes `docs/ux-spec.md` (which still describes the OLD "PhoenixAudit" dark OKLCH attack-matrix theme — that work is dead). No color, font, layout, or component shape gets reinvented; the port follows the designer's CSS variables, IBM Plex Mono / Newsreader / Instrument Sans typography, paper/ink + ember chamber palette, custom primitives, and inline-style + CSS-variable hybrid approach.
- **Do NOT install shadcn/ui** — the designer built every primitive custom (Toggle, Field, EmptyState, SectionHead, Stamp, Citation, Tag, OptCard, Seal, Glyph, Wordmark, PageFoot). Story 7.1's shadcn requirement is a relic of the OLD ux-spec and is dropped. Saves 50+ install hops, zero design fidelity loss.
- **No mocks in the hot path** (CLAUDE.md §14 absolute). The live audit route (`/run/[runId]`) MUST consume the real SSE stream from `phoenix-audit-agent`. Designer's deterministic-timeline-driven prototype stays as the engine for `/replay` (the pre-recorded canonical demo) AND as a backfill for per-probe events the backend `/stream` does not yet emit (the backend currently emits `phase_change` + `complete` only; per-probe `test_started`/`test_completed`/`cluster_set`/`recipe` events are Epic 5/6 work the backend hasn't streamed yet). The bridge is documented honestly in code; it is not a mock — it's the visual scaffolding around the real phase events the backend DOES emit.
- **All eleven designer routes ship**: `/`, `/new`, `/replay`, `/run/[runId]`, `/audits`, `/agents`, `/agents/[id]`, `/recipe/[recipeId]`, `/report/[runId]`, `/monitoring`, `/settings`, `/states`. Plus `app/opengraph-image.tsx` rendering the designer's `og.html` via `next/og`. Plus `/health` for the existing Cloud Run liveness probe.
- **Fixture data lives in `lib/fixtures.ts`** with TypeScript types aligned to `packages/shared-types/hardening-recipe.json`. The single fictional customer (Meridian Mutual Health, prior-authorization agent, run `run_9f3c2ab81d4e`) is preserved verbatim — every page is wired through one coherent world.
- **All animations preserved**: page-enter rise stagger, phase-node pulse-ring, verdict-in scale-bounce, blink-caret, seal-spin (36s linear), receipt slide-in, cascade-flip dot-converge overlay, film-grain SVG turbulence. `prefers-reduced-motion: reduce` opts every animation out (already in the designer's CSS).
- **Existing CI gates must pass**: ruff (Python — unaffected), `ty check` (Python — unaffected), ESLint + tsc on `phoenix-audit-web`, `scripts/check_max_lines.py` (≤400 lines per file — designer's largest file is `audit.jsx` at 448 lines, so we split it during the port), `prettier --check`, conventional-commit titles, gitleaks. Pre-existing Dockerfile uses Next.js standalone output — we honor that.
- **No file >400 lines.** The designer's `audit.jsx` (448), `wizard.jsx` (193), `landing.jsx` (329) all approach or exceed the cap. Splitting into per-component files happens during the port.
- **One Epic 7 PR per logical slice** — the original 12-story Epic 7 breakdown is too coarse for what the designer shipped (the designer covered ~21 surfaces' worth of work). We re-cut the work into focused PRs, each landing one or two designer files' worth of features, each with a green CI run, per CLAUDE.md "one PR per story, eggs in one basket."
- **No file mocks the backend types.** All TypeScript types referencing audit-run / hardening-recipe / failure-cluster come from a single typed source matching the locked backend schema (`packages/shared-types/hardening-recipe.json`) — extend the existing shared-types if needed.

## Acceptance

1. **Build green.** `pnpm --filter phoenix-audit-web build` exits 0 in clean checkout. `pnpm --filter phoenix-audit-web typecheck` (tsc --noEmit, strict) exits 0. ESLint passes (max-lines: 400, no-console, consistent-type-imports). Prettier passes.
2. **All 11 routes render.** `pnpm --filter phoenix-audit-web dev` boots; `curl -sf http://localhost:3000/{,/new,/replay,/audits,/agents,/agents/agt_priorauth,/recipe/recipe_7c0d51e2a9b4,/report/run_9f3c2ab81d4e,/monitoring,/settings,/states}` returns HTTP 200 for each. `/run/[runId]` returns 200 and opens an EventSource against `NEXT_PUBLIC_AGENT_URL/stream`.
3. **Visual fidelity to anchor.** The designer's 16 anchor screenshots in `/Users/abu/Downloads/Phoenix Audit/shots/` (landing, sweeps, probe, recipe) get checked into `apps/phoenix-audit-web/screenshots/anchor/`. The sahil-visual-loop reviewer (`/code-review --visual` equivalent) returns `verdict === "ok"` with `blocking_count = 0` per page. Pixel diff tolerance set to the designer's actual variance.
4. **Cascade-flip works.** Loading `/replay` and scrubbing to t=17.2s produces the three-failure-dots-converging-to-one-cluster overlay. The cluster card transitions from "awaiting judge phase" → "settled" between t=17.2s and t=18.8s. Verified by Playwright video assertion (or manual capture if time-constrained).
5. **Real SSE works.** Hitting `/run/run_9f3c2ab81d4e` while `phoenix-audit-agent` is running locally (or on staging) advances the phase rail from `queued` → `injector` → `judge` → `patcher` → `succeeded` driven by the real `phase_change` events. The SSE event feed shows the real wire lines.
6. **Cloud KMS signing animation.** On `/report/[runId]`, clicking "Sign and file" plays the 2.1s `signing` veil with the spinning seal, then transitions to `signed` state showing the seal stamp on the cover page. Download PDF / Download signed JSON buttons appear (no-op placeholders permitted; the real PDF generator is Epic 6 work not yet shipped).
7. **OG image renders.** `GET /opengraph-image` returns a 1200×630 PNG matching the designer's `og.html` (cascade diagram + seal + EU AI Act footer).
8. **States gallery complete.** `/states` shows all 8 designer state cards (empty / target unreachable / SSE error / signing key blocked / cap reached / GitLab broken / fallback marker / loading) — these double as design QA fodder and as the source of truth for error-state copy.
9. **Hosting-mode toggle round-trips.** Switching `/settings` between default and BYO writes to localStorage; the wizard's §3 BYO block appears/disappears accordingly.
10. **Reviewer pass in fresh context.** A fresh-context reviewer agent (pr-review-toolkit or sahil-pr-audit) reviews the final PR(s) against the SPEC + the original story BDD criteria + the designer's anchor screenshots, returning `verdict: ok` per page surface.
